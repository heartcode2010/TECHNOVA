# TECHNOVA delivery roadmap

This roadmap follows the master product brief. Dates are planning horizons, not delivery guarantees.

## Phase 0 — repository and product foundation

**Work**
- Inspect the TECHNOVA repository, source repositories, branches, commit history, deployment, manifests, environment variables, database and external integrations.
- Record a known-good baseline and restorable backup.
- Inventory every protected Scanner and Academy path, route, component and dependency.
- Import source snapshots with provenance and licenses; do not edit the originals.
- Audit Dark Obsydia before integration.
- Establish CI, formatting, tests, security checks, observability and rollback.
- Define new-module design tokens and navigation without restyling protected products.

**Exit criteria**
- Source inventory and dependency map reviewed.
- Protected-path manifest and regression checks exist.
- Backup and rollback procedure verified.
- Build and test commands run successfully.
- No protected files modified.

## Phase 1 — first useful Nigerian release

### ScamShield
- Accept pasted text and URLs first; file/image intake only after safe upload and extraction.
- Explain suspicious indicators, evidence, uncertainty and next steps.
- Include Nigerian patterns: fake transfer alerts, impersonated bank support, job/recruitment fees, fake grants and cloned business pages.
- Never call an item safe merely because no indicator was found.
- Add rate limits, reporting guidance, privacy controls and abuse moderation.

### FixIt
- Guided issue intake for phone, laptop, Windows, software, Wi-Fi, website and code issues.
- Ask only essential follow-up questions.
- Give ordered, reversible steps and warnings before destructive actions.
- Save case history and user-confirmed resolution; paid remote support only with explicit consent.

### Opportunity Radar
- Start with editorially verified sources and manual review.
- Store source URL, organisation, date checked, deadline, eligibility and status.
- Expire stale listings; never invent grants, jobs, deadlines or sponsors.
- Add saved items and application tracking after source quality is reliable.

### Portfolio and Business Launchpad MVP
- Portfolio: user-controlled profile and project evidence.
- Business: invoices/quotes and basic product/customer records.
- Payments are recorded as pending until confirmed by signed provider events.

**Exit criteria**
- Complete real journeys with persistence, permissions, loading/error/success states and mobile QA.
- Support and moderation procedures exist.
- No fabricated data or fake provider states.

## Phase 2 — build and demonstrate ability
- Build-to-Launch guided product workspace.
- TechLabs isolated HTML/CSS/JS execution and preview.
- Arena challenge engine with fair scoring and anti-cheat review.
- Community Projects with moderation and ownership rules.

**Exit criteria:** users can create, test, save, share and prove work without exposing platform infrastructure.

## Phase 3 — work and income
- Freelance Exchange and MicroWorks pilots.
- Scoped listings, proposals, milestones, delivery evidence, disputes and auditable records.
- Payment protection only through a compliant, contracted provider after legal review.
- Digital Resource Library with rights/ownership checks.

## Phase 4 — education and institutions
- QuizVerse/EduVerse and Nigerian CBT preparation.
- Campus and institution roles.
- Cyber Range isolated practice.
- Skill-to-Income pathways tied to verifiable work.

## Expansion
Website Guardian, TECHNOVA Pulse, TrustCheck, PriceWatch, NetPulse, PowerPulse, DeviceCare, LocalVoice, API Hub, Digital Vault, CivicTech Navigator, Nexora and Web3 Forge. Each requires validated demand, an operational owner, security review and sustainable unit economics.

## Definition of done for every module

- A real user can complete the core task.
- Inputs are validated; permissions are enforced.
- Data persists and can be exported/deleted appropriately.
- Loading, empty, error and success states are meaningful.
- Mobile and low-bandwidth behaviour is tested.
- Security, privacy, abuse and accessibility are reviewed.
- Logs, metrics, support documentation and rollback exist.
- Tests pass and the exact release is verified.
